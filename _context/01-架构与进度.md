````markdown
## 四、核心机制

### 4.1 分步展示

```
SlideView（父）
  ↓ provideStep(1) —— 创建 step 上下文
  ↓
子组件（版式）
  ↓ useStepCount(() => 步数)
  ↓ 直调 stepCtx.setMax(n)
  ↓
StepWrapper（子）
  ↓ 显示当前 step 及之前的内容
```

**数据流**：
- **往下** —— `current` / `max`（provide）
- **往上** —— `setMax(n)`（子组件调用）

### 4.2 数据懒加载

```
首次进入某讲 → 异步 import('./lesson-XX.js') → 缓存
再次进入 → 从缓存拿
```

**效果**：首屏从 900KB → 130KB。

### 4.3 版式自动注册

```js
// slides/index.js
const modules = import.meta.glob(['./*Slide.vue', '../animations/*Slide.vue']);
````

````markdown
## 三、教学设计原则

### 3.1 "问题驱动" 优先

**不先给定义** —— **先问"为什么需要它"**。

**例**（lesson-02）：
- ❌ 直接讲"变量是什么"
- ✅ 先问"没有变量，程序怎么存数据？"—— 用 `origin` 讲"从内存地址到名字的演进"

### 3.2 三类知识分层

| 类型 | 呈现方式 |
|---|---|
| **概念** | origin / dialog / grid |
| **代码** | code-split / evolution |
| **练习** | level-map / quiz |

### 3.3 "伏笔 - 回收" 跨讲联动

**每讲埋伏笔**（如"0 和 1 → 第 22 讲"）—— **后续讲回收**。

**标记**：数据里用 `🔮 伏笔` / `🔮 回收伏笔`。

**自动扫描**：`generate-index.js` 生成"伏笔清单"。

### 3.4 每讲"三要素"

**每讲必须有**：
1. **一个核心概念**（`core`）—— 一句话
2. **3-4 个子知识点**（`points`）—— 逐轮讲
3. **一个跨讲联结**（`fore`）—— 埋或收

### 3.5 教学节奏模板

```
回顾 → 目标 → 地图 → 概念 → 代码 → 练习 → 小测 → 总结 → 作业 → 预告
```

**约 25-35 页 / 讲** —— 一节课 45 分钟或学生自学 1.5 小时。

## 九、教学质量的判断标准

**做对了**：
- 学生**能看懂为什么**（不只"是什么"）

- 学生**有印象**（伏笔 / 故事 / 图片）

- 只堆知识点，不问"为什么"
- 页数多但节奏乱
- 每页都"一样密"或"一样空"
- 学生学完记不住核心
````

````markdown
# 课程开场设计规则

> 适用于：任何讲次的前 3-5 页设计，尤其是零基础第一课、新阶段开场课。
> **核心原则**：先给震撼 / 成就，再讲理论。

---

## 一、三声哇开场模型

在前 15 分钟内，必须完成以下 3 步：

| 顺序 | 动作 | 目的 | 推荐组件 |
|---|---|---|---|
| 第一声哇 | 看效果 | 建立“这东西很酷”的第一印象 | code-split（3-5 行代码 + 惊艳输出） |
| 第二声哇 | 上手做 | 打破“我不会”的心理壁垒 | split（环境配置 + 步骤） |
| 第三声哇 | 看反馈 | 建立“我做到了”的成就感 | big-number（大字 + 仪式感） |

---

## 二、组件选型规范

| 场景 | 推荐组件 | 避免 |
|---|---|---|
| 开场震撼 | code-split（少代码 + 大效果） | dialog（长篇大论） |
| 环境配置 | split（左图右步骤） | grid（文字太多） |
| 仪式感 | big-number / quote | dialog |
| 原理前置 | origin（三层演进） | dialog（长篇对话） |
| 历史时间线 | timeline（精简至 6 项内） | 超过 10 项 |

---

## 三、必须避免的 5 个错误

1. **前 10 分钟没有代码** —— 学生会睡着
2. **用长篇对话讲抽象概念** —— 如“程序是什么”用 8 轮 dialog
3. **历史时间线超过 8 项** —— 全是陌生名字，记不住
4. **没有“仪式感”** —— 学生不知道自己学会了什么
5. **先讲“为什么”再动手** —— 顺序反了

---

## 四、适用边界

- **适用于**：lesson-01（零基础第一课）、lesson-07 / 11 / 25 等新板块开场
- **不适用于**：中间讲次（学生已有基础，可直接进入“问题驱动”）
````

````markdown
## 三、加一个新版式（组件）

### 3.1 命名约定

**新建 `src/components/slides/XxxSlide.vue`** —— **自动注册**为 `xxx` type。

| 文件名 | 注册的 type |
|---|---|
| `CoverSlide.vue` | `cover` |
| `CodeSplitSlide.vue` | `code-split` |
| `BigNumberSlide.vue` | `big-number` |

### 3.2 组件模板

```vue
<template>
  <SlideShell :slide="slide">
    <!-- 内容 -->
    <StepWrapper v-for="(item, i) in items" :key="i" :step="i + 1">
      <div>{{ item }}</div>
    </StepWrapper>
  </SlideShell>
</template>

<script setup>
import { computed } from 'vue';
import SlideShell from '@/components/common/SlideShell.vue';
import StepWrapper from '@/components/common/StepWrapper.vue';
import { useStepCount } from '@/composables/useStepCount';

const props = defineProps({
  slide: { type: Object, required: true }
});

const d = computed(() => props.slide.data || {});
const items = computed(() => d.value.items || []);

useStepCount(() => items.value.length);
</script>
```

### 3.3 用 SlideShell 的好处

- **自动处理**：标题 / 副标题 / 章节标签 / extra
- **自动追加**：`extra` 折叠卡（可通过 `:auto-extra="false"` 关闭）
- **统一样式**：`.slide` / `.slide-title` / `.slide-body`

### 3.4 支持 footer

**参考 `GridSlide.vue`**：

```vue
<StepWrapper v-if="footer" :step="footerStep">
  <SlideFooter :html="footer" />
</StepWrapper>
```

**脚本**：
```js
const footer = computed(() => d.value.footer);
const footerStep = computed(() => items.value.length + 1);
useStepCount(() => items.value.length + (footer.value ? 1 : 0));
```
````

````markdown
# 课件设计与重构 SOP（教学标准操作规程）

> **最高准则（道）**：上课的质量才是中心。节奏、内容、扩展、趣味等，全都是为此服务。
> **执行原则（术）**：绝不为了“套用版式”而拆碎逻辑；绝不为“展现专业”而堆砌超纲干货。当某个重构方案会破坏课堂的连贯性时，果断放弃方案，回归教学本质。
> **血泪教训**：为了“好提炼”而把课塞满卡片，会变成无情的 PPT 朗读机；为了“抓眼球”而强加梗，会打碎学生的注意力。

---

## 一、重构时的六大设计考量维度

### 维度 0：知识链路与前置依赖审查（防断层）
在动笔重构任何一讲之前，必须先做“知识链路审查”。绝对禁止使用学生尚未学过的语法或函数来制造冲突或作为演示。
1. **前置依赖三问**：
   - 这个语法/函数，在当前讲次前面的页面讲过吗？
   - 它在之前的讲次讲过吗？
   - 如果都没讲过，**必须先讲怎么用，再讲怎么坑**。
2. **冲突与痛点设计的正确递进链路**：
   - ❌ 错误链路：直接演示 `getline` 发生车祸（但学生根本不知道 `getline` 是什么）。
   - ✅ 正确链路：先用旧工具 `cin` 读带空格句子失败（痛点）→ 引出救星 `getline` 并演示正常用法（建立认知）→ 演示 `cin` 和 `getline` 混用导致空行（高阶巨坑与解法）。
3. **重构交付前的自查清单**：
   - 检查每一页出现的所有 `code` 和 `函数名`，确保都在“当前页之前”或“历史讲次”中介绍过。

### 维度 1：认知负荷管理（别把学生的大脑当硬盘）
1. **单页信息密度上限**：一页 `grid` 最多 4 张卡；`code-split` 右侧注释最多 5 条。超过则必须拆页。
2. **抽象概念必须“具象化”**：绝不在学生没有具体经验时，先抛学术名词。
   - *错误示范*：第 4 页就甩出“四站学习地图”。
   - *正确做法*：先用“3 行代码画三角形”给视觉冲击，再在总结页回收地图。
3. **信息必须可提炼**：要求学生记住的（初赛考点、语法规则），必须用 `grid` 或 `compare` 形式呈现，绝不可埋在废话连篇的 `dialog` 里。

### 维度 2：注意力曲线与悬念释放（课不能是一条直线）
1. **15 分钟一个波峰**：如果连续 3 页都是平铺直叙的 `grid`，学生必然犯困。必须用以下版式“提神”：
   - `big-number`（视觉冲击，如 21 亿）
   - `pitfall`（雷区警示，如 cin 的坑）
   - `quote`（金句/情感，如 AC 是礼物，WA 是老师）
2. **痛点/高潮前置**：像“整数溢出”这种认知冲突，必须紧跟在“int 范围”之后立刻演示，不能憋到最后。
3. **【新增】分步动画的悬念释放机制（严禁剧透）**：
   - 在使用 `code-walkthrough` 或 `evolution` 等带步骤的组件时，`intro`（静态引导文字）**绝对不可提前剧透最终的冲突结果**（如：“答案不是 2147483648”）。
   - **正确做法**：`intro` 只负责平稳铺垫（“我们跑个程序看看”），悬念和反转必须依靠 `steps` 的按步高亮和变量突变来引爆（第一步是正常值 → 第二步突变负数 → 第三步解释原因），让学生的惊呼声留在按键翻页的那一刻。
4. **喘息点**：两道高强度 `level-map`（练习）之后，必须跟一页“软内容”（如 `split` 图文故事，或趣味扩展），让大脑降温。

### 维度 3：动机与逻辑连贯性（防断裂）
1. **先想动手，再给门槛**：绝对禁忌“想跑 Hello World 却被塞了一堆配置”。必须做到“选工具 → 跑起来 → 优化配置”。
2. **引子与解法紧贴**：抛出问题（如 21 亿溢出），下一页立刻演示问题（code-walkthrough），再下一页给解法（long long）。中间不能插播不相干的语法。
3. **“讲”与“练”的边界（双总结机制）**：
   - **老师讲的总结**（`quote` 版式）：放在作业前，通过金句和要点，带学生快速回顾一遍，情感收束。
   - **学生用的教案**（`grid` 版式）：必须放在最后（结束页前），提供结构化的知识卡片。这一页老师**不需要逐字带读**，只需说一句“大家掏出手机，把这一页拍下来，这就是今天最重要的复习资料”，把时间留给学生自己消化。

### 维度 4：练习（level-map）的脚手架与节奏控制
1. **趁热打铁，绝不打包（防疲劳）**：严禁把多个 `level-map` 堆在讲次末尾。必须遵循**“讲完一个核心坑 → 立刻跟一道题 → 收束”**的节奏。连续做题会让大脑迅速疲劳，失去检查代码的耐心。
2. **去重与减负（考点的唯一性）**：如果两道题本质上考的是同一个逻辑（例如：一道题坑在 `9/5`，一道题坑在 `(double)a/b`），**果断删掉一道**。保留那道结合了公式和场景的题即可，切勿为了练而练。
3. **警惕“注水小结”**：刚做完一道题，立刻用一整页 `grid` 去总结“刚才那道题的要点”，纯属浪费课堂时间。把这道题的 `analysis` 讲透即可，省下的时间留给初赛考点或小测。
4. **Hints 不能直接给答案（引导思考）**：
   - 第一层 Hint：暗示**卡点在哪**（“仔细看公式里的除法，小心陷阱”）
   - 第二层 Hint：暗示**思考方向**（“9/5 会得到 1，怎么让它变成 1.8？”）
   - 第三层 Hint：**点出语法解法**（“用 (double) 强制转换”）
5. **Analysis 要点出思维误区**：解析不能只贴代码，要解释“为什么你这么想会错”。

### 维度 5：词汇认知与敬畏心（编程不是敲乱码）
1. **缩写词必须拆解（拆字法）**：...
2. **【新增】结尾的情感升华与行动号召（忌用“点击返回”）**：
   - 绝对禁止在 Ending 页只写“点击返回目录”，这像关闭网页。
   - 必须使用 `EndingSlide` 的 `extra` 字段（自动带光晕特效）进行升华。
   - **结构**：肯定今天的成就（如：你的程序学会了判断） → 抛出下一节的终极悬念（如：一秒执行一亿次的魔法） → 具体的刷题号召。
3. **故事性（origin / quote）**：初高中学生需要知道，这个语法是无数前辈踩坑、流血（如阿丽亚娜火箭爆炸）换来的。好课程是一张网，不是一条线。
4. **伏笔与回收（埋雷与拆雷）**：讲 `int` 提到了“21 亿怎么来的”，必须精准指向第 22 讲的二进制，不能说完就忘。
5. **课外扩展要有“冲击力”（拒绝枯燥的产品说明）**：
   - 扩展知识不能只列举“高大上的应用场景”（如 AI、数据处理），这在学生眼里叫“背书”。
   - **必须加入“惊险故事”、“黑客历史”或“反直觉的硬核事实”**。
   - 示例：讲死循环，用“AT&T 电话网大瘫痪”来震撼；讲数组越界，用“黑客缓冲区溢出攻击”来建立敬畏心；讲浮点数，用“阿丽亚娜火箭爆炸”来说明。
   - 只有让学生觉得“原来这玩意儿这么危险/厉害”，兴趣点才算真正被点燃。
6. **设置课堂“呼吸点”，但必须克制（Fun Break）**：
   - 连续高密度输出后，需要让学生脑子宕机 2-3 分钟。
   - **克制原则**：整堂课**最多插入 1 页**放松内容（如使用 `split` 或 `quote`）。
   - **选材原则**：只挑 1-2 个最经典的“网络爆款梗”（如：买包子与买西瓜的逻辑冲突），不要贪多。
   - **收束原则**：笑完之后，底部的 `footer` 必须**立刻“敲黑板”**，把笑话和刚学的知识点（如 `if-else` 的歧义）挂钩，瞬间把注意力拉回课堂。

### 维度 6：代码层面的硬性规范（防报错）
1. **引号嵌套转义**：JS 字符串内部如果包含 HTML 属性，外层一律用单引号 `''`；如果包含单引号，外层用双引号 `""`，严禁制造出多余的 `\`。
2. **optionLayout 显式声明**：`QuizSlide` 必须写明 `optionLayout: "vertical" | "horizontal" | "two-cols" | "code"`，杜绝启发式推断导致的排版崩溃。
3. **slide id 绝对连续**，`total` 与页数绝对一致。
4. **代码文件分离原则（工程化规范）**：
   - 为了保证可以用脚本进行一键编译检查（verify-codes），以及方便后续单独修改代码。
   - **严禁**在 JS 数据中使用冗长的内联 `code: "..."` 或 `\n` 拼接来写大段代码。
   - 只要是需要展示给学生看、需要学生敲击的代码（如 `code-split` 的演示代码），**一律使用 `codeFile: "codes/lesson-XX/xxx.cpp"` 的格式**引用外部文件。
   - 只有极短的伪代码、或者 1-2 行的结构示意（如 `summary.code`），才允许使用内联 `code`。

### 维度 7：机房实战与“急救”防翻车（教练保命法则）
1. **“急救卡片”机制（红线预警）**：
   - 课件不能只讲“正确的做法”，必须预判学生“搞砸后的惨状”。
   - 在涉及运行环境、输入格式、嵌套边界的页面（如 `code-split` 或 `level-map`），必须使用红字标出 **“🚨 急救预警 / 救命小贴士”**。
   - 典型场景：Dev-C++ 闪退（别乱点，举手）、`cin` 输入报错（千万别敲逗号）、`endl` 位置（写在内层就是一列，写在外面才是行）。
2. **超纲知识克制（防认知崩塌）**：
   - 严禁在任何阶段为了“炫技”或“严谨”引入当前未学到的语法点。
   - 例如：在 Lesson 03（类型转换）刚学完 bool 时，讲浮点数不精确，只讲现象（0.1+0.2≠0.3），绝不可引入 `fabs` 函数或 `1e-8` 的差值比较法，因为学生还没学 `if` 和 `<cmath>`。必须留到后续章节。
3. **易混淆语法的“防晕提示”**：
   - 对于打破常规思维的“高级技巧”（如 `switch` 的 `case` 穿透，不写 `break`），在讲解时必须增加免责声明：“这里是故意不写的，初学者自己写代码时务必老老实实加上 `break`，切勿轻易模仿！”

## 二、版式与内容的匹配指南（干湿分离）

**⚠️ 旧规范清理**：我们**删除了**过去“一刀切将 dialog 替换掉”的教条。版式没有优劣，只有是否匹配内容。

| 信息类型 | 首选版式 | 备选版式 | 禁忌 |
| :--- | :--- | :--- | :--- |
| **悬念/灵魂拷问** | `big-number` | `quote` | 不可用 `grid` 一堆字 |
| **变量状态变化** | `code-walkthrough` | `evolution` | 不可用 `code-split` 静态看 |
| **痛点场景/共鸣** | `dialog`（真实场景对话） | `pitfall` | 不可用 `grid` 干巴巴列点 |
| **对比辨析** | `compare` | `split` | 不可用文字长篇大论 |
| **初赛考点/规则** | `grid` (卡牌化) | `timeline` | **绝不可用 `dialog`** |
| **历史演进/故事** | `origin` | `timeline` | - |

## 三、标准重构流程

每次拿到一课（如 lesson-03.js），按以下 5 步执行：

1. **诊断（抓取痛点）**：扫一遍代码，找出：
   - 连续超过 3 页的纯文字/grid（容易困）。
   - 用错版式的页（如用 dialog 讲初赛考点）。
   - 脱离学生实际经验的抽象名词。
2. **重排（调动机）**：调整页序，确保“引入（问题）→ 冲突（演示）→ 理论（解释）→ 解法（代码）”的连贯。
3. **调味（加血肉）**：在平铺直叙中间，插入 `pitfall`、`quote`（真实灾难/名言）、`big-number`。
4. **提炼（固骨架）**：把规则和坑点，改写成 3-4 张 `grid` 卡片，方便学生截图复习。
5. **体检（防报错）**：检查 `id`、`total`、`optionLayout`、转义字符。

## 四、页序节奏参考（以 lesson-02 为样板）

*   **破冰（p1-3）**：封面 → 回顾 → 目标。
*   **引入（p4-6）**：起源（为什么需要） → 具象化比喻 → 过渡。
*   **基础实践（p7-13）**：代码演示 → 练习 → 埋坑（pitfall）→ 规律总结（grid）。
*   **核心重灾区（p14-20）**：过渡 → **震撼（big-number）→ 翻车（walkthrough）→ 解药（code-split）→ 指南（decision）→ 实战（level-map）**。
*   **次级概念（p21-25）**：过渡 → 情境探讨（dialog，可用） → 代码演示 → 练习。
*   **收束拓展（p26-33）**：初赛（grid）→ 趣味（grid）→ 小测（quiz）→ 总结（quote）→ 作业 → 预告 → 答疑（grid）→ 结束。
````

````markdown
## 三、grid 卡片数量

**推荐**：**1 / 2 / 3 / 4 / 6 / 8 / 9 / 12**（对称）

if (n === 1) return 'grid-cols-1';

if (n % 3 === 0) return 'grid-cols-3';
return n >= 8 ? 'grid-cols-4' : 'grid-cols-3';

## 四、extra vs footer

| 工具 | 用途 | 展示 | 例子 |
|---|---|---|---|
| **extra** | 长故事 / 跨学科 | **折叠** | Ada Lovelace、阿丽亚娜火箭 |

**判断**：
- **内容 ≤ 3 行** → footer
- **> 3 行 或 有故事性** → extra
- **不确定** → 用 footer（简化页面）

## 五、图片使用

### 5.2 用 ImageCard 组件

```js
extra: {
  title: '📖 冯·诺依曼结构',
  image: {
    src: 'static/images/people/von-neumann.jpg',
    alt: '约翰·冯·诺依曼',
    caption: '约翰·冯·诺依曼（1903—1957）',

    layout: 'float-right',
    size: 'sm'
  },
  desc: '...'
}
```

**layout**：`float-right` / `float-left` / `block` / `inline`
**size**：`sm`（160px）/ `md`（280px）/ `lg`（480px）/ `full`

**统一放 `public/static/images/`** —— 按类别分：
- `people/` —— 人物
- `events/` —— 事件
- `concepts/` —— 概念图

## 六、扩展页（人物 / 事件专页）

**什么时候做扩展页**：
- 有"人物 + 事件 + 反差"
- 内容够 1 页（不只 1 段）
- 和当前讲主题强相关

**用什么组件**：
- **人 / 事件** → `split`（左图右文）
- **问题** → `origin`
- **时间线** → `timeline`

**示例**（ENIAC 页）：
```js

        title: '关键数据',

          { title: '📊 规模', desc: '...' },

        ]
      }
    ]
  }
````
