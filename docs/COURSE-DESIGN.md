## 一、课程背景

| 项 | 内容 |
|---|---|
| 课程名 | 《小C的C++冒险》 |
| 对象 | 6 年级—初二，学过 Scratch，零 C++ 基础 |
| 目标 | 零基础 → CSP-J 一等奖 → CSP-S 入门 → NOIP 长线 |
| 每讲时长 | **120 分钟** |
| 上课频率 | 一周一次课 |
| 课后时间 | 少，练习以课堂为主 |
| 教学模式 | 统一教学，题目分难度 |
| 总讲次 | 约 57 讲（1.5 年完成，不固定上限） |

### 1.1 四条底层目的（判断课程好坏的最终依据）

1. 为只学过图形化的学生教学 C++
2. 使之具备参加比赛的能力
3. 课堂知识点覆盖竞赛知识
4. 内容丰富有趣，知识面扩展

## 二、设计原则

### 2.1 七条核心原则

| # | 原则 | 说明 |
|---|---|---|
| 1 | **每讲一个核心抽象概念** | 2—4 个子知识点 |
| 2 | **课堂练习占 1/3 以上** | 课后时间少，练习当堂做 |
| 3 | **每讲开头复习 10 分钟** | 一周一次课，遗忘严重 |
| 4 | **难度分层，进度不分层** | 统一教学，题目分 ⭐/⭐⭐/⭐⭐⭐ |
| 5 | **算法思维从第 5 讲渗透** | 不等语法学完再讲算法 |
| 6 | **每阶段末一次实战** | 模拟赛 + 错题精讲 + 知识串讲 |
| 7 | **难度 × 数量综合评估** | 见第三章评估框架 |

### 2.2 课堂节奏（120 分钟）

```
复习上节        10 分钟
新知识讲解      45 分钟
课堂练习        35 分钟（当堂做，当堂讲）
总结 + 答疑     20 分钟
下节预告        10 分钟
```

### 2.3 题目分层机制

| 档位 | 位置 | 目标人群 | 占比 |
|---|---|---|---|
| ⭐ 基础 | level-map 练习 1 | 所有人必做 | 50% |
| ⭐⭐ 进阶 | level-map 练习 2 | 大部分人能做 | 30% |
| ⭐⭐⭐ 挑战 | level-map 练习 3（选做） | 学有余力者 | 20% |

课后作业：**统一用洛谷题，0—3 道**。详见 5.12。
知识清单页附“挑战题单”（3—5 道洛谷题号，按难度排序）。

## 三、难度评估框架

### 3.1 单点难度分级

| 等级 | 负荷值 | 特征 |
|---|---|---|
| ⭐ | 1 | 直观、无前置、无动态 |
| ⭐⭐ | 2 | 略有抽象，或有前置 |
| ⭐⭐⭐ | 4 | 抽象 / 反直觉 / 动态，三者占一 |
| ⭐⭐⭐⭐ | 7 | 三者占二 |
| ⭐⭐⭐⭐⭐ | 10 | 三者全占，或需多步推理 |

**三个维度**：
- **抽象度**：概念是否看不见摸不着
- **反直觉度**：是否违反日常经验
- **动态性**：是否涉及“过程 / 变化”

### 3.2 每讲总负荷

**总负荷 = Σ（单点负荷 × 关联折扣）**

关联折扣：
- 同一概念展开的多个点，合并计 **0.7**
- 独立概念，各计 **1.0**

### 3.3 每讲负荷区间（120 分钟）

| 区间 | 总负荷 | 判断 | 处理 |
|---|---|---|---|
| 偏轻 | < 12 | 内容不足 | 加知识点或挑战题 |
| 合适 | 12—18 | 理想 | 保持 |
| 偏重 | 18—24 | 内容过密 | 减内容或拆讲 |
| 过载 | > 24 | 必须拆 | 拆成两讲 |

### 3.4 评估示例

**例：第 9 讲 递归**

| 知识点 | 难度 | 负荷 | 关联 |
|---|---|---|---|
| 递归概念 | ⭐⭐⭐⭐ | 7 | 独立 |
| 三要素 | ⭐⭐⭐⭐ | 7 | 与概念 ×0.7 |
| 阶乘 | ⭐⭐⭐ | 4 | 与三要素 ×0.7 |
| 斐波那契 | ⭐⭐⭐⭐ | 7 | 与递归 ×0.7 |
| 汉诺塔 | ⭐⭐⭐⭐⭐ | 10 | 与递归 ×0.7 |

总负荷 = 7 + 4.9 + 2.8 + 4.9 + 7 = **26.6 → 过载**

**处理**：汉诺塔改为选学，斐波那契移到第 20 讲 DP 前。
调整后 = 7 + 4.9 + 2.8 + 2.8 = **17.5 → 合适**

### 3.5 难度曲线要求

- 每 2—3 讲安排一个难点（⭐⭐⭐⭐）
- 难点后紧跟缓冲讲（⭐⭐⭐）
- 单讲不出现两个 ⭐⭐⭐⭐⭐ 知识点
- 阶段末实战不计入负荷

## 四、完整课程结构

### 4.1 五阶段总览

| 阶段 | 讲次 | 主题 | 目标 |
|---|---|---|---|
| 一 | 1—10 | 编程基础 | 能写 50 行程序，CSP-J 第一题稳过 |
| 二 | 11—24 | 算法入门 | CSP-J 第二题稳过 |
| 三 | 25—35 | 数据结构 | CSP-J 第三题有思路 |
| 四 | 36—50 | 竞赛进阶 | CSP-S 入门 |
| 五 | 51+ | 冲刺实战 | CSP-J/S 拿分 |

### 5.4 认知节奏规则

**页面分为两类**：

| 类别 | 包含类型 | 特征 |
|---|---|---|
| **高负荷页** | code-split / evolution / function-call-animation / hanoi-animation / dp-table-animation / binary-search-animation | 需要学生持续集中注意力 |
| **低负荷页** | dialog / grid / quote / transition / cover / ending / glossary | 学生可稍放松 |

**排列规则**：

| # | 规则 | 说明 |
|---|---|---|
| 1 | 高负荷页不连续出现 3 页 | 连续 3 页 code-split 会疲劳 |
| 2 | 高负荷页后紧跟 1 页低负荷页 | 缓冲 |
| 3 | 每讲高负荷页总数 ≤ 8 | 超过会拖节奏 |
| 4 | 每 5 页内至少 1 页低负荷页 | 保证节奏起伏 |
| 5 | 每 3—5 页有 1 页过渡页 | 承上启下 |
| 6 | 无连续 3 页同 type | 即使都是低负荷，也不连续同 type |

**例外条款**（4 条）：

| # | 例外 | 来源 | 理由 |
|---|---|---|---|
| 1 | `level-map` 练习 3 道可连续 3 页 | lesson-01～08 惯例 | 三道练习连做符合教学直觉 |
| 2 | 同一主题变体可连续 3 页 code-split（如 `if` / `if-else` / `if-else if`） | lesson-04 | 同一主题的多个变体放一起更清晰 |
| 3 | `evolution` 和 `transition` 视作"半对话页" | lesson-05 | dialog 间隔从"实际 dialog 页"开始计算 |
| 4 | 同一主题的多个变体（如 `char vs string` / `char[]` / `string`）可连续 3 页 code-split | lesson-07 | 同类内容放一起对比学习 |
| 5 | **阶段实战**（第 10/24/35/50 讲）不适用"dialog ≥ 4 页" | lesson-10 | 以模拟赛 + 精讲为主 |
| 6 | 挑战题的**演示页 + 解析页**可连续 2 页同 type | lesson-10 | 教学需要"先解析，后演示" |

### 5.6 代码示例规范

| 项 | 要求 |
|---|---|
| 变量名 | 见名知意，不用 `a`/`b`/`c`（除非是数学变量） |
| 缩进 | 4 空格 |
| 注释 | 每 3—5 行至少 1 条 |
| 输出格式 | 与 OJ 题目一致 |
| 代码长度 | `code-split` 单页 ≤ 15 行 |
| snippet 标记 | 独立一行，成对出现 |
| 函数命名 | 小写 + 下划线，如 `is_prime` |
| 常量命名 | 全大写，如 `MAXN` |

**正例**：
```cpp
// 判断 n 是否为质数
bool is_prime(int n) {
    if (n < 2) return false;
    for (int i = 2; i * i <= n; i++) {
        if (n % i == 0) return false;
    }
    return true;
}
```

**反例**：
```cpp
bool f(int x) {
    if (x < 2) return 0;
    for (int i = 2; i * i <= x; i++)
        if (x % i == 0) return 0;
    return 1;
}
// 问题：函数名无意义、无注释、缩进不统一
```

### 5.7 常见错误要求

每讲必须包含 **至少 1 页 `compare`** 或 **1 条 Extra** 专门讲常见错误。

**常见错误来源**：

| 来源 | 举例 |
|---|---|
| 本讲新语法易错点 | 循环忘写 `i++` |
| 前一讲遗留易错点 | 整数除法丢小数 |
| 竞赛高频错误 | 数组越界、边界条件 |

**格式要求**：

```js
{

  title: '本讲常见错误',
  data: {

      { wrong: '错误写法', right: '正确写法' },
      { wrong: '错误原因', right: '正确原因' }

    extra: {
      title: '📖 四大错误的原因',
      desc: '① …… ② …… ③ …… ④ ……'
    }
  }
}
```

**质量要求**：
- 至少 3 组对比
- Extra 中逐条解释原因
- 关联本讲 slide 编号
- **不得引入超纲知识点**（如 1 讲不能出现二维数组）

### 5.9 动画使用规则

**使用原则**：

> 动画只在“过程看不见”时才加。
> 静态页能讲清 → 不加动画。

**三条铁律**：

| # | 原则 | 说明 |
|---|---|---|
| 1 | “看不见”才加 | 过程在代码里看不清中间状态 → 加动画 |
| 2 | “重复 3 次”才建组件 | 同一场景出现 3 次以上 → 才值得新建组件 |
| 3 | “静态能讲清”不加 | 代码 + 注释 + 图能讲明白 → 不要为好看加动画 |

**组件选择**：

| 场景 | 推荐组件 |
|---|---|
| 表达式逐层展开 | `evolution` |
| 函数调用 / 递归栈 | `function-call-animation` |
| 一维序列变化 | `stack` / `queue` / `sort` / `linked-list` |
| 二维结构变化 | `hanoi` / `tree` / `graph` |
| 静态网格填充 | `dp-table` |
| 区间减半 | `binary-search` |
| 纯文本 / 公式 | 不用动画 |
| 静态流程 | `flow` |

**数量与位置**：

| 项 | 要求 |
|---|---|
| 每讲动画页 | ≤ 3 页 |
| 动画页位置 | 概念后、练习前 |
| 若含 3 个动画 | 主体页压到 12 页以内 |
| 组件复用 | 优先复用现有组件，不新建 |

### 5.13 可选趣味扩展页

**定位**：在最后一题（level-map 练习 3）之后，插入一页**趣味扩展**，作为难题后的放松与文化扩展。

**性质**：**可选，非必备**。

**核心原则**：

> **不硬塞。有就扩展，没有就下一步。**

判断三问：

| # | 判断三问 | 是 / 否 |
|---|---|---|
| 1 | 本讲主题有没有“有趣的历史 / 文化 / 故事 / 梗”？ | |
| 2 | 这个故事能不能让学生“哇”一下？ | |
| 3 | 加了会不会拖节奏？ | |

**三问都“是” → 加；任一“否” → 跳过。**

**位置**：
```
level-map 练习 3（最后一题）
↓
【可选】趣味扩展页
↓
quiz 课堂小测
```

**组件选择**：

| 场景 | 推荐组件 |
|---|---|
| 展示多张图 / 作品集 | `grid` |
| 讲一个完整故事 | `dialog` |
| 一句话 + 一张图 | `quote` / `split` |
| 多个案例对比 | `compare` |

**内容来源**（参考方向，非强制）：

- 名人轶事（高斯、图灵、冯·诺依曼）
- 文化现象（字符画、程序员梗、佛祖保佑）
- 现实应用（导航算法、微信聊天记录）
- 历史故事（汉诺塔传说、ENIAC）
- 网络梗（TODO: fix this later）

**约束**：

| 项 | 要求 |
|---|---|
| 每讲上限 | ≤ 1 页 |
| 建议时长 | 3—5 分钟 |
| 与初赛渗透的区别 | 初赛渗透为**考点**服务；趣味扩展为**兴趣**服务 |
| 与 Extra 的区别 | Extra 附在组件内；趣味扩展**独占一页** |
| 与答疑的区别 | 答疑**解惑**；趣味扩展**扩趣** |

**反例（不要硬塞）**：

| 场景 | 判断 |
|---|---|
| 本讲主题是“变量定义”，找不到有趣故事 | 跳过 |
| 故事牵强，学生听了无感 | 跳过 |
| 只是为了“凑满页数” | 跳过 |

### 5.15 挑战题的思路演示

**规则**：**每讲的 ⭐⭐⭐ 挑战题，必须配 1 页"过程演示"**。

**演示方式**（按题类型）：

| 题类型 | 演示组件 |
|---|---|
| 递归 / 枚举 | `function-call-animation` 或 `tree-animation` |
| 递推 / DP | `dp-table-animation` 或 `evolution` |
| 排序 / 二分 | `sort-animation` 或 `binary-search-animation` |
| 图 / 树遍历 | `graph-animation` 或 `tree-animation` |
| 字符串处理 | `evolution` 或 `dialog` + 伪代码 |

**位置**：level-map 练习 3 之后、小结之前。

**页数**：+1 页，`total` 同步 +1。

**例外**：如果挑战题只需"文字解析"就能讲清（如纯逻辑题），可省略演示页。

### 5.16 长代码处理规范

| 代码长度 | 处理方式 |
|---|---|
| ≤ 20 行 | 整段显示（不写 snippet） |
| 20—50 行，关键区域连续 | snippet 单段 |
| 20—50 行，关键区域不连续 | split 组件（多栏对照） |
| > 50 行 | 拆成多页，每页 ≤ 20 行 |
| 需分段高亮同一段长代码 | evolution + `focusLines` |

**拆页原则**：
· 第 1 页：框架（函数签名 + 主流程）
· 第 2—N 页：按逻辑分段（循环 / 递归 / 输出）
· 最后一页：完整代码（可选）
