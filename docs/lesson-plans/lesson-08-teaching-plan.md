## 🎯 五大核心节点速览

### 节点 1：钩子 · 复制粘贴的灾难（0:00-0:05）
- **【教师操作】**：提问算 100 个圆面积，改 \(\pi\) 精度怎么办。
- **【关键台词】**：“程序员最讨厌复制粘贴，改漏一个就全盘皆输。我们需要把代码‘打包’，这就是函数。”
- **【学生状态】**：共鸣，体会到代码复用和易维护的重要性。

### 节点 2：第一次冲突 · 找不到标识符（0:05-0:15）
- **【教师操作】**：让学生封装 `printStar()` 写在 `main` 后，F11 报错。
- **【关键台词】**：“编译器是从上往下看的，你在下面写的函数，上面的 `main` 根本不认识。记住解药：函数要么写在上面，要么提前声明。”
- **【学生状态】**：被编译报错毒打，记住代码顺序。

### 节点 3：核心揭示 · 数学映射（0:15-0:30）
- **【教师操作】**：黑板上画加工机，讲解 \(y = f(x)\) 到 `int square(int x)` 的映射。
- **【关键台词】**：“`x` 是形参（占位符），你传入的 `5` 是实参。函数是个黑盒，用 `return` 吐结果。如果返回类型是 `int`，你忘了写 `return`，机器直接卡死。”
- **【学生状态】**：理解函数的输入与输出结构。

### 节点 4：第二次冲突 · 交换惨案（0:40-0:50）
- **【教师操作】**：让学生写 `swap(int a, int b)`，在 `main` 里调用后打印，发现 `x, y` 根本没交换。
- **【关键台词】**：“凭什么在 `main` 里写能交换，装进函数就失效了？难道函数有内鬼？”
- **【学生状态】**：极度震惊，逻辑崩塌，怀疑人生。

### 节点 5：揭示与收束 · 复印件魔法（0:50-1:05）
- **【教师操作】**：用 `cout << &a` 打印 `main` 里的 `x` 和函数里的 `a` 的地址，投屏展示两个截然不同的十六进制内存地址。
- **【关键台词】**：“它们根本不在同一个房间！C++ 默认传参，传的是**复印件**，不是原件。你把复印件撕了，原件当然没变。这就叫值传递，这也是为什么函数里的局部变量出了门就销毁。”
- **【学生状态】**：倒吸凉气，彻底理解值传递机制。

## 🚑 机房急救卡
1. **现象**：函数调用报错 `'xxx' was not declared`。
   **解药**：把函数定义剪切到 `main` 前面，或者把声明写在前面。
2. **现象**：函数报错 `expected return value`。
   **解药**：检查函数返回类型是否是 `void`。如果不是，确保所有条件分支最后都有 `return`。
